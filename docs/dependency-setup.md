# Dependency setup

Open **Dependency setup…** at the top of Frontier Pilot, including before a career has been created. The menu gives one next instruction and three numbered steps. Downloaded and installed are separate states; existing downloads are reused and verified before launch.

**Detect and recheck** shows a completion time even if nothing changed. A Core-only installation populates the SDK folder and specifically identifies missing Samples; it remains unavailable for use until all required files and hashes pass. A selected incomplete installation is kept visible rather than replaced by another incomplete candidate.

1. **Install SDK Core:** download Core (264 MB), then choose **Install Core…** and finish Microsoft's wizard. Keep its suggested SDK folder. A cached download enables Install Core directly; installed/verified Core does not need downloading again.
2. **Install SDK Samples:** this step becomes available only after Core passes verification. Download Samples (3.2 GB), then choose **Install Samples…** and finish its wizard. The launcher supplies the verified Core folder. Cached Samples can be installed directly, without another download.
3. **Check and finish:** **Check installation** finds SDK installations in the selected folder, fresh environment configuration, Windows installer registry and common locations. When all required components pass, **Finish setup** saves the user-level MSFS2024_SDK setting and updates the current application. Closing an installer also refreshes these checks automatically. Downloading alone never completes a step.
4. **SDK folder and connection details** contains the custom-folder picker, technical status and Community2024 path read from MSFS UserCfg.opt. Detection never modifies scenery. Downloads pin SDK 1.2.4; the current survey implementation cannot accept a newer version automatically. Close MSFS and Package Tool before installation. Cancellation is available during download/extraction; once Windows Installer is open, use its own Cancel action. SDK settings/downloads remain separate from career data.
5. Load a flight and use the existing connection checks. Successful dependency setup does not establish simulator compatibility or survey qualification.

The downloader streams into unique local folders, checks available space and download length, bounds archive sizes, and extracts only the MSI and its sibling CAB payloads to fixed filenames. ZIP paths cannot choose extraction destinations. Redirects and arbitrary download URLs are refused. The MSI must have a valid Microsoft Corporation Authenticode signature both after downloading and immediately before launch. Missing/cancelled/failed downloads cannot enable installation. Windows installer exit codes are reported; SDK discovery and exact component hashes, not an installer exit alone, determine readiness.

Samples installation now requires verified Core files first. The app reads fresh machine-level SDK configuration, supplies the selected Core root in the installer environment and MSFS_SDK property, and writes a verbose installation log beside the downloaded MSI. Microsoft MSI product/version metadata identifies cached components without executing installer actions; previous Samples downloads can be retried after reopening the app without downloading again. Cached MSI signatures are rechecked before launch.
