## Boundaries and source map

| Responsibility | Authority |
|---|---|
| Person/group identity, declared kg, carriage states and station ownership | Core `PassengerTransport.cs`; no employer, wage or aircraft-specific policy |
| Mission count/purpose and eligible company aircraft types | Workflow `EmployedPassengerMissions`; route catalogue guards still apply at both endpoints |
| Configuration-backed capacity and optional limits | `IPassengerAircraftConfigurations`; production exact-hash Caravan profile, synthetic profiles only inside tests |
| Intent/write/readback/recovery | `PassengerPayloadCoordinator`, existing `IAircraftLoadingSimulator` snapshots and guarded native setter |
| Qualified flight and airborne duration | Existing tracker passenger monitor, shared distance/stationary/time helpers; carriage arrival is not independent delivery evidence |
| Wages/payment | `PassengerTransferKernel`, authoritative economy ledger; unchanged Offshore $800 and Missionary $400 per verified airborne hour |

The shared aggregate can be used without an employed assignment or financial transaction. Future commercial sources can reserve groups and use the coordinator, then apply their own mission/settlement rules. No ticket/fare/airline-management behavior is implemented.

Reservation creates stable person/group IDs. UI manifest entry requires one positive kg weight per person, with no assumed default body weight. The shared lifecycle is Planned → Reserved → Boarding → Aboard → Arrived → Disembarking → Disembarked. Arrival is authorized by the mission adapter using the existing tracker proof. Employment assignments retain accepted route snapshots, purpose, eligible aircraft, flight progress and hourly wage policy separately.

Missionary adds a doctor and community liaison visiting a catalogue community. Existing Missionary destination/database/manual-review gates determine routes; unresolved destinations stay unavailable. No new hospital/clinic coordinates or scenery inspection claims were added. The eligible C208 profile is distinct from company cargo dispatch budgets. Offshore remains Vision Jet policy; new physical Vision Jet boarding is blocked pending its effective configuration. Already-boarded schema-11 simulated Offshore flights can still finish under their existing rules.

## Physical loading and recovery

Only empty configured passenger areas are allocated. A nonempty area has unknown occupant count and is preserved/unavailable. Pilot/copilot, existing cargo and other payload remain untouched. Known station/payload/gross limits apply before a write. Ground/stopped actual aircraft, exact company mapping, selected physical fleet GUID and mission endpoint are rechecked. Fuel is never written by this coordinator; any change during verification prevents confirmation. Stop engines for the focused acceptance procedure.

The economy saves group weights, configuration fingerprint, selected GUID, owned station names/indices, original baseline, added passenger mass/count, protected station weights and absolute targets **before** writing. A cross-process named lease serializes Frontier cargo/fuel/passenger operations. The interim positive cargo/passenger exclusion is checked inside atomic economy mutations as well as dispatch/recovery guards, closing the check-then-write race. The shared domain permits disjoint/mixed carriage; the current careers do not enable mixed Frontier assignments yet. Unrelated manually loaded MSFS cargo is preserved.

The production setter compares actual identity, location, station names/weights and fuel again in the same native session immediately before writing. It uses distinct read definitions for each read. Immediate and separate retained snapshots, separated by cargo's existing three-second retention interval, must confirm owned targets, protected stations, gross delta, ground/location, time and reported CG limits. Tests explicitly simulate that wait and assert it occurs. SimConnect has no transactional compare-and-swap with manual EFB edits: do not edit or swap aircraft while an operation is running. Late inconsistencies retain an unresolved intent, never guessed success or rollback. Aircraft retention beyond that observation remains part of live acceptance.

On a partial failure, the saved intent remains Boarding/Disembarking with a visible error. Explicit Board/Disembark retry accepts each managed station only at the saved before value or full target, writes only remaining absolute targets and verifies again. An intermediate/manual value, altered name/configuration/GUID or changed protected payload blocks the operation. Inspect the error and simulator, restore the saved expected state only when its provenance is understood, then retry. There is no silent overwrite/adopt/force-clear action. Unknown conflicts require investigation; do not edit the save to bypass them.

Unloading requires tracker-qualified arrival and matching owned aboard mass. It snapshots current unrelated payload, persists removal targets, then verifies removal of only owned mass to the baseline. Missing passenger mass **before** an unload intent is a conflict, not inferred delivery. A pending unload whose targets already match can recover without removing mass twice. A durable verified unload can settle the employed mission after a crash without another simulator write. Terminal mission/flight/wage/balance commit remains one atomic revision with one wage ledger entry.

Disconnect/restart/telemetry gaps pause new physical passenger flight proof until **Check payload after reconnect** succeeds in the recorded selected aircraft. The check is read-only and does not invent flown time. Fresh tracker stationary/arrival observations still apply. No automatic boarding, restoration or payment occurs on ordinary refresh. A verified unload receipt allows explicit settlement recovery even offline. Complete or resolve existing cargo manifests/recovery before starting passengers; resolve pending passenger actions before cargo.
