# Guided cargo loading: implementation and acceptance

Matt reported the new Cargo dispatch screen failing at **Prepare preview while walking outside**, with “Type is invalid”, on the Black Square Caravan Professional Cargo Pod. The screenshot showed 5 kg and 100 kg selected, matching station totals, zero confirmed aboard, and both jobs Reserved. It establishes a failed live preview, not a successful payload write, nor the precise source of the missing identity field.

## Investigation and limits
`FlightAircraftIdentity.EnsureValid` rejected missing `Type` with the unhelpful message. The prepare path can reach it from the fresh native aircraft read or the separately tracked aircraft identity during avatar authorization. The preserved local career binding/loading identity fields inspected read-only were nonempty; no personal state was changed or copied into this repository. The exact failing runtime stage was not previously recorded, so it is **unconfirmed** which source was incomplete. Do not describe a bounded retry as proof the aircraft-specific live fault is solved.

The adapter still requests aircraft proxy 0, independently of avatar/current proxies. Comparing with `checkpoint-loading-live-verified-2026-09-17` shows native station/unit read/write mechanics largely retained; the multi-stop orchestration is new. No evidence supports replacing aircraft identity with avatar, a guessed type, or an old cached value. Microsoft's [object-type documentation](https://docs.flightsimulator.com/msfs2024/html/6_Programming_APIs/SimConnect/API_Reference/Structures_And_Enumerations/SIMCONNECT_SIMOBJECT_TYPE.htm) distinguishes aircraft/avatar/current, and [aircraft.cfg](https://docs.flightsimulator.com/msfs2024/retail/content-configuration/cfg-files/aircraft.cfg/) defines `atc_model` separately from other aircraft identifiers. Those SDK facts do not qualify this exact live aircraft.

## Changes
- Incomplete native identity reads retry at most three times with 250 ms waits and fresh reads on the same session. No identity fallback or automatic write retry. Persistent absence still refuses loading with a specific explanation. Normal guarded write comparison/readback behavior is unchanged.
- Missing tracked aircraft model during outside/seated cargo checks gets a transition-specific blocker. Prepare failures report the phase (existing records, native identity/payload, tracking/avatar access, cargo/dispatch/stations or persistence), and explicitly state the preview did not write payload. Full exception details remain in collapsed technical details.
- The primary loading button stays fixed at the bottom of the viewport and changes from **Confirm loading / unloading plan** to **Apply cargo in cockpit** once durable intent exists. **Load available cargo** and **Deliver cargo for this airport** select logical quantities, retaining through-cargo. Partial quantities remain editable before confirmation. No mass or inventory changes occur merely by choosing quantities.
- Choose the actual cargo compartment once; the button reconciles aggregate station mass automatically. No guessed seat/cargo mapping, limit or MTOW/CG/performance decision. Advanced distributions, explicit renewal/discard and diagnostics remain collapsed. Pending/active-flight quantities are locked in the UI; backend guards remain authoritative.
- Destination and one stateful departure button replace separate plan/arm controls. Ten continuous stopped tracking seconds and explicit start remain required; no automatic proof, wages or arming. Existing jobs and pay policy are unchanged.
