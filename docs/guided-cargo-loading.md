Aggregate delivery reductions preserve explicit new pickup targets and unrelated baseline. Station ownership remains aggregate, not a new persistent per-consignment physical-location claim. Existing pending targets/manifest remain the restart authority; unconfirmed UI selections are discarded on refresh/restart. Advanced totals and diagnostics stay collapsed. ## Changes
- Incomplete native identity reads retry at most three times with 250 ms waits and fresh reads on the same session. No identity fallback or automatic write retry. Persistent absence still refuses loading with a specific explanation. Normal guarded write comparison/readback behavior is unchanged.
- Missing tracked aircraft model during outside/seated cargo checks gets a transition-specific blocker. Prepare failures report the phase (existing records, native identity/payload, tracking/avatar access, cargo/dispatch/stations or persistence), and explicitly state the preview did not write payload. Full exception details remain in collapsed technical details.
- The primary loading button stays fixed at the bottom of the viewport and changes from **Confirm loading / unloading plan** to **Apply cargo in cockpit** once durable intent exists. **Load available cargo** and **Deliver cargo for this airport** select logical quantities, retaining through-cargo. Partial quantities remain editable before confirmation. No mass or inventory changes occur merely by choosing quantities.
- Choose the actual cargo compartment once; the button reconciles aggregate station mass automatically. No guessed seat/cargo mapping, limit or MTOW/CG/performance decision. Advanced distributions, explicit renewal/discard and diagnostics remain collapsed. Pending/active-flight quantities are locked in the UI; backend guards remain authoritative.
- Destination and one stateful departure button replace separate plan/arm controls. Ten continuous stopped tracking seconds and explicit start remain required; no automatic proof, wages or arming. Existing jobs and pay policy are unchanged.
